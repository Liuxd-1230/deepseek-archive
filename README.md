# DeepSeek 对话存档

一个浏览器扩展。你在网页版 DeepSeek 问问题，它一边往外吐字，这个扩展一边把原话抄下来存到你自己的电脑上；等它说完了，再去找 DeepSeek 要一份整理干净的正式版本存起来。之后你可以导成 Markdown 文件。

要解决的问题很具体：**DeepSeek 正在输出、还没输出的时候就要开始记录**，而不是等它说完。因为有些内容事后会拿不到（下面"为什么要边说边抄"讲了原因）。

## 装和用

1. 浏览器打开 `edge://extensions`（或 `chrome://extensions`），开「开发者模式」
2. 「加载已解压的扩展程序」，选这个项目文件夹
3. **扩展详情里把「网站访问权限」改成「在所有网站上」**。默认是"仅在单击时允许"，那样脚本根本进不了网页，表现就是什么都录不到
4. 打开 `https://chat.deepseek.com/`，正常提问
5. 点工具栏图标开侧栏，左下角能看到存档列表，右下角能导出

侧栏顶部有个**「自检」**按钮，不工作时先点它。它按链条一项一项查：后台在不在跑 → 网页脚本进没进去 → 堵没堵到出数据的请求 → 抄到字没有 → 存进本地库了没。哪一项红，问题就在哪。

**「备份全部」**把整个存档（含原始帧）导成一个 JSON 文件，换电脑、重装浏览器前点一下；**「恢复备份」**读回来。不想留的存档选中后点「删除」，包括"未关联会话"的孤儿原始帧。

## 隐私

所有数据只存在你自己浏览器的 IndexedDB 里。这个扩展不联网、不上报、没有任何统计代码，唯一的网络活动是 DeepSeek 页面自己发请求时被旁路记录。注意备份出来的 JSON 是明文，里面有完整对话内容，自己保管好。

## 为什么设计成两条路

**第一条（正式存档）**：等 DeepSeek 说完，调它自己的 `history_messages` 接口拿完整对话。好处是拿到的是**原始 Markdown**（表格还是竖线写法，能原样喂回模型），思考全文也在，分支结构也在。

**第二条（原始抄录）**：它一边说，一边把网络上传过来的原始文本按到达顺序原样存盘，**一个字符都不解析**。

第二条存在的理由：第一条要等"说完之后"才去拿，而如果内容在事后被服务端撤回或改写，就再也拿不到了。已经抄到硬盘上的字节不受影响。解析器写坏了、字段改名了，都能拿原始文本重跑。

## 关于安全栅栏（0.1.3 已实测）

DeepSeek 的审核是**先发送、后擦除**（用真实触发样本确认）：正文一帧不少地推到浏览器之后，最后一帧 BATCH 才把 `status` 改成 `CONTENT_FILTER`，并用一条 `TEMPLATE_RESPONSE`（"你好，这个问题我暂时无法回答…"）把 `fragments` 整体换掉。页面上的表现就是文字出现了又消失。

**被擦的原文在原始帧里，一字不缺，思维链也在。** 侧栏选中会话时，扩展自动把原始帧里的 `{p,o,v}` 操作流重放一遍：**被过滤的回答直接内联显示**（思考折叠、正文直读，橙色边条标注，并附上页面实际显示的模板话术作对照）；没有正式存档的会话则全部重建。「导出 Markdown」会自动带上这些内容：无正式存档的会话直接导出重建版，有正式存档但被过滤的回答以附录附在导出末尾；原始帧列表里每条流后面也会标出「被过滤 · 已恢复 N 字」。正式存档走的是事后接口，拿到的只是过滤后的最终状态，所以重建是恢复原文的唯一来源。

如果某条流重建出来是空的（连覆盖帧都没有），说明服务端在审核阶段就没把字节往下发，任何浏览器侧手段都救不回来——这是架构上限，不是 bug。

## DeepSeek 网页的实际情况（实测，不是猜的）

这些是逆向它的打包文件和真机抓包得到的，改代码前值得先看一眼。

**传输方式**：流式回答走的是 `XMLHttpRequest`，**不是 fetch**。第一版实现堵在 fetch 上，实测一个字都没抓到，而页面照常出答案。

**协议形状**：不是 OpenAI 那种 `delta.content` 增量。帧载荷是 `{p, o, v}` 三元组——路径、操作（`SET` / `BATCH` / `APPEND`）、值，相当于把一串操作应用到一份文档上。已确认的事件名有 `ready`、`update_session`、`close`。这就是为什么"只存原始字节、离线再解析"是划算的：实时解析这套东西既贵又脆。

**一条回答不是一个字符串，是若干 fragment**：

| 类型 | 内容 | 备注 |
|---|---|---|
| `REQUEST` | 用户提问原文 | |
| `THINK` | 思考全文 | 实测比正文长 3.5 倍，带 `elapsed_secs` |
| `RESPONSE` | 正文，原始 Markdown | 实测表格、粗体都是源码形态 |
| `TOOL_SEARCH` / `TOOL_OPEN` | 联网搜索结果 | **结构未实测**，触发联网才出现 |
| `TIP` | 固定提示语（"内容由 AI 生成…"） | 无信息量，侧栏灰字一行、导出不带 |

**消息是树不是列表**：`message_id` + `parent_id`，重新生成和编辑提问都会产生兄弟分支。所以主键必须带 `message_id` 并保留 `parent_id`，否则不知道录的是哪一支。

**判"说完了"**：没有 `[DONE]` 这种终止符。看消息上的 `status`（取值有 `FINISHED` / `CONTENT_FILTER` / `CONTEXT_LENGTH_EXCEEDED` / `INCOMPLETE` / `WIP` / `TIMEOUT`），配合 `has_pending_fragment` 和 `incomplete_message`。**只看连接关闭会把被 token 上限截断的回答误判成完整。**

**为什么不走 DOM 抓取**（这是最初的想法，被实测否掉了）：
- 消息列表是虚拟化的（`ds-virtual-list`），屏外的消息节点被卸载，长对话抓不全
- 思考区完成后折叠，实测 API 里 7797 字的思考全文，DOM 里只剩 1871
- DOM 是渲染态，表格已经变成 `<table>`，Markdown 源码不可逆
- 网页上 108 个按钮**没有一个有 `aria-label` / `title` / `data-testid`**，想靠界面认控件只能靠 SVG 图标路径，改版就废

**几个能白捡的便利**：
- 会话 ID 直接写在地址里：`/a/chat/s/<uuid>`，那个 UUID 就是 `chat_session_id`，不用嗅探
- 调接口用的令牌在 `localStorage.userToken` 的 `.value`（**不是** `settingsJwt`，用那个会返回 `INVALID_TOKEN`）
- 类名只有 `ds-` 前缀的可依赖；`_24fad49` 这种下划线开头的是构建哈希，每次发版都变

## 文件结构

```
manifest.json              扩展清单，声明三个注入点
src/recorder-main.js       注入到网页自己的环境，拦 XMLHttpRequest（+ fetch 兜底），抄原始文本
src/recorder-bridge.js     注入到隔离环境，校验握手暗号后批量转发给后台
src/content.js             隔离环境：调 history_messages、回自检问询
src/background.js          后台：判断流开始/结束、收原始文本、写库、更新图标角标
src/normalize.js           把接口返回的字段名映射成内部结构
src/db.js                  IndexedDB 读写（扩展自己的存储，不是网页的），含备份/恢复
src/markdown.js            导出 Markdown，含分支标注和异常提示
src/rebuild.js             原始帧回放器：重放 {p,o,v} 操作流，重建被 CONTENT_FILTER 擦除前的原文
sidepanel/                 侧栏界面：会话列表、重建视图、导出、备份/恢复、自检
icons/                     扩展图标（tools/make-icons.mjs 生成，纯 Node 无依赖）
test-rebuild.mjs           回放器测试：node test-rebuild.mjs
```

一个刻意的设计：**IndexedDB 只在后台和侧栏里访问**。内容脚本里写 IndexedDB 会落到 `chat.deepseek.com` 这个域名下——侧栏读不到，而且网站清缓存就能抹掉你的存档。所以内容脚本只负责同源取数据，数据一律传给后台再落盘。

## 还没做的

- `TOOL_SEARCH` / `TOOL_OPEN` 的真实字段结构。需要一个真会触发联网的问题。
- 后台进程如果在流结束那一瞬间正好休眠，这次存档会漏。侧栏的「补抓本页存档」是手动兜底，彻底解决要上定时任务。
- 每次拉的是**整个会话**再覆盖写，长对话偏浪费。够用，可优化成增量。
- 没有自动清理策略。空间占用在「自检」里能看到；多了就手动删会话，或者先「备份全部」再删。
- 只支持 DeepSeek。要加别的站点，得把接口地址、字段映射、结束判据抽成可配置的适配层。

改完代码记得：扩展页点「重新加载」，并**刷新 DeepSeek 标签页**——旧页面里跑的还是旧脚本。

## 一句话原则

**不要轮询 DeepSeek 的接口。** 只在流结束时取一次。它家有针对导出功能的限流，高频拉取可能影响你的账号。
