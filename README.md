# DeepSeek 对话存档

一款浏览器扩展，用于在网页版 DeepSeek 生成回答的同时，将流式输出逐字记录至用户本地；回答结束后再通过其官方接口获取一份完整的正式存档。存档内容可随时导出为 Markdown 文件。

本扩展解决的核心问题是：**记录必须发生在回答生成过程中，而非结束之后**。部分内容在回答完成后可能无法再次获取（详见「为何采用双路存档」）。

## 安装与使用

1. 在浏览器中打开 `edge://extensions`（或 `chrome://extensions`），启用「开发人员模式」。
2. 点击「加载解压缩的扩展」，选择本项目所在文件夹。
3. **在扩展详情页将「网站访问权限」设置为「在所有网站上」**。默认的「仅在单击时允许」会导致内容脚本无法注入页面，表现为完全无法记录。
4. 打开 `https://chat.deepseek.com/`，正常提问即可，存档过程无需人工干预。
5. 点击工具栏图标打开侧边栏：左下角为存档列表，右下角为导出入口。

侧边栏顶部提供**「自检」**功能，扩展无法正常工作时应优先使用。自检按链路逐项检查：后台服务是否运行 → 页面脚本是否注入 → 是否成功拦截数据请求 → 是否捕获到内容 → 是否写入本地数据库。任一项标红即表明问题位于该环节。

**「备份全部」**可将全部存档（含原始帧）导出为单个 JSON 文件，适用于更换设备或重装浏览器前的数据迁移；**「恢复备份」**用于将备份文件读回。选中存档后点击「删除」可将其移除，包括未关联到任何会话的孤立原始帧。

## 隐私说明

所有数据仅存储于用户本机浏览器的 IndexedDB 中。本扩展不进行任何网络上报，不包含统计或埋点代码；唯一的网络相关行为是在 DeepSeek 页面自身发起请求时进行旁路记录。请注意：备份导出的 JSON 文件为明文，包含完整对话内容，请妥善保管。

## 为何采用双路存档

**第一路（正式存档）**：在回答结束后调用 DeepSeek 自身的 `history_messages` 接口获取完整对话。其优点在于返回内容为**原始 Markdown**（表格保持源码形态，可直接回喂模型），且思考全文与分支结构完整。

**第二路（原始抄录）**：在回答生成过程中，将网络传输的原始文本按到达顺序原样落盘，**不做任何解析**。

第二路的必要性在于：第一路必须等待回答结束后才能执行，若内容在事后被服务端撤回或改写，将无法再次获取；已落盘的字节不受服务端操作影响。此外，即使解析器存在缺陷或协议字段发生变更，也可基于原始文本重新解析。

## 内容过滤机制（0.1.3 已实测验证）

DeepSeek 的审核策略为**先下发、后擦除**（已通过真实触发样本确认）：正文完整推送至浏览器后，最后一帧 BATCH 才将 `status` 置为 `CONTENT_FILTER`，并以一条 `TEMPLATE_RESPONSE`（"你好，这个问题我暂时无法回答…"）整体替换 `fragments`。页面上的表现是文字先出现后消失。

**被擦除的原文完整保留在原始帧中，思维链亦不缺失。** 侧边栏选中会话时，扩展会自动重放原始帧中的 `{p,o,v}` 操作流：**被过滤的回答将内联显示**（思考内容折叠、正文直读，以橙色边条标注，并附页面实际显示的模板话术作为对照）；缺少正式存档的会话则整体重建。「导出 Markdown」自动包含上述内容：无正式存档的会话直接导出重建版本；有正式存档但被过滤的回答以附录形式附于导出末尾；原始帧列表中每条流亦会标注「被过滤 · 已恢复 N 字」。由于正式存档来自事后接口，仅能获取过滤后的最终状态，因此重建是恢复原文的唯一途径。

若某条流重建结果为空（连覆盖帧都不存在），说明服务端在审核阶段即未下发字节，任何浏览器侧手段均无法恢复——此为架构层面的上限，而非缺陷。

## DeepSeek 网页版协议要点（基于逆向分析与实机抓包）

以下内容来自对前端打包产物的逆向分析与实机抓包，修改代码前建议先行阅读。

**传输方式**：流式回答使用 `XMLHttpRequest`，**而非 fetch**。首版实现拦截 fetch，实测未捕获到任何数据，而页面回答正常输出。

**协议形态**：与 OpenAI 的 `delta.content` 增量模式不同。帧载荷为 `{p, o, v}` 三元组——路径、操作类型（`SET` / `BATCH` / `APPEND`）、值，等价于对一份文档依次应用操作序列。已确认的事件名包括 `ready`、`update_session`、`close`。这正是"仅存储原始字节、离线再行解析"策略合理的原因：实时解析该协议成本高且脆弱。

**单条回答由若干 fragment 组成，而非单一字符串**：

| 类型 | 内容 | 备注 |
|---|---|---|
| `REQUEST` | 用户提问原文 | |
| `THINK` | 思考全文 | 实测比正文长 3.5 倍，带 `elapsed_secs` |
| `RESPONSE` | 正文，原始 Markdown | 实测表格、粗体都是源码形态 |
| `TOOL_SEARCH` / `TOOL_OPEN` | 联网搜索（`queries`/`results`）/ 打开网页（`result`） | 已实测；正文 `[reference:N]` 是指向工具片段的 `{id,type}` 指针，导出时还原成可点链接 |
| `TIP` | 固定提示语（"内容由 AI 生成…"） | 无信息量，侧栏灰字一行、导出不带 |

**消息结构为树而非列表**：以 `message_id` + `parent_id` 组织，重新生成与编辑提问均会产生兄弟分支。因此主键必须包含 `message_id` 并保留 `parent_id`，否则无法区分所记录的属于哪一分支。

**回答结束的判定**：不存在 `[DONE]` 之类的终止符。需依据消息的 `status` 字段（取值包括 `FINISHED` / `CONTENT_FILTER` / `CONTEXT_LENGTH_EXCEEDED` / `INCOMPLETE` / `WIP` / `TIMEOUT`），并结合 `has_pending_fragment` 与 `incomplete_message` 综合判断。**仅以连接关闭作为结束依据，会将因 token 上限被截断的回答误判为完整。**

**不采用 DOM 抓取的原因**（最初方案，经实测否决）：
- 消息列表经过虚拟化（`ds-virtual-list`），视口外的消息节点会被卸载，长对话无法完整抓取；
- 思考区域在完成后折叠，实测 API 返回的 7797 字思考全文在 DOM 中仅剩 1871 字；
- DOM 属于渲染结果，表格已转换为 `<table>`，Markdown 源码不可逆；
- 页面上 108 个按钮均**不具备 `aria-label` / `title` / `data-testid`**，若依赖界面识别控件只能借助 SVG 图标路径，版本更新即失效。

**若干可直接利用的便利条件**：
- 会话 ID 直接体现在地址栏中：`/a/chat/s/<uuid>`，该 UUID 即 `chat_session_id`，无需嗅探；
- 接口调用令牌位于 `localStorage.userToken` 的 `.value`（**注意并非** `settingsJwt`，后者会返回 `INVALID_TOKEN`）；
- 类名中仅 `ds-` 前缀者可以依赖；`_24fad49` 之类下划线开头的名称为构建哈希，每次发版都会变化。

## 文件结构

```
manifest.json              扩展清单，声明三个注入点
src/recorder-main.js       注入页面主环境，拦截 XMLHttpRequest（fetch 兜底），记录原始文本
src/recorder-bridge.js     注入隔离环境，校验握手标识后批量转发至后台
src/content.js             隔离环境：调用 history_messages 接口、响应自检问询
src/background.js          后台：判定流开始/结束、收集原始文本、写入数据库、更新图标角标
src/normalize.js           接口字段名到内部结构的映射
src/db.js                  IndexedDB 读写（扩展自身存储，与页面隔离），含备份/恢复
src/markdown.js            Markdown 导出，含分支标注与异常提示
src/rebuild.js             原始帧回放器：重放 {p,o,v} 操作流，重建被 CONTENT_FILTER 擦除前的原文
sidepanel/                 侧边栏界面：会话列表、重建视图、导出、备份/恢复、自检
icons/                     扩展图标（由 tools/make-icons.mjs 生成，纯 Node 实现、无外部依赖）
test-rebuild.mjs           回放器测试：node test-rebuild.mjs
```

一项刻意的架构约束：**IndexedDB 仅在后台与侧边栏中访问**。在内容脚本中写入 IndexedDB 会使数据落到 `chat.deepseek.com` 域名之下——侧边栏无法读取，且网站清除缓存即可删除存档。因此内容脚本仅负责同源取数，数据一律交由后台落盘。

## 已知限制与后续计划

- 若后台服务工作进程恰好在流结束瞬间处于休眠状态，本次存档将丢失。侧边栏的「补抓本页存档」为手动兜底手段，彻底解决方案需引入定时任务。
- 每次拉取均为**整个会话**并覆盖写入，长对话存在冗余。当前可用，后续可优化为增量同步。
- 暂无自动清理策略。存储占用可在「自检」中查看；空间不足时可手动删除会话，或先执行「备份全部」再行删除。
- 目前仅支持 DeepSeek。如需支持其他站点，需将接口地址、字段映射、结束判据抽象为可配置的适配层。

修改代码后请注意：在扩展管理页点击「重新加载」，并**刷新 DeepSeek 标签页**——已打开的页面仍运行旧版本脚本。

## 使用原则

**请勿轮询 DeepSeek 接口。** 仅在流结束时获取一次。该平台针对导出类功能设有限流措施，高频拉取可能对账号造成影响。
